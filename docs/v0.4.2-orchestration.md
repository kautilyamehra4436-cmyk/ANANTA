# ANANTA v0.4.2 — Additive orchestration

## Purpose
v0.4.2 adds an orchestration layer around the existing deterministic control modules. It does not replace their implementations.

## Execution sequence
1. VAK parses and validates the task request.
2. MANAS creates a focused task representation.
3. BUDDHI creates the current deterministic plan.
4. PRAMANA assesses attached evidence.
5. SAKSHI flags claims without attached evidence.
6. RITA validates the orchestration dependency graph.
7. The controller assembles the response and records audit events.

The sequence is defined as a dependency graph and ordered through the existing RITA topological-order implementation. The orchestration layer reports the actual stage order in `execution_order`.

## Preservation and compatibility
- Existing module implementations remain in `src/ananta/modules.py`.
- Existing data contracts remain in `src/ananta/models.py`.
- Existing audit and execution implementations remain in their original files.
- `src/ananta/orchestration.py` is additive.
- The controller delegates pipeline coordination to the new layer while preserving its public `process()` result fields; `execution_order` is an additional field.
- Package and project metadata versions are aligned at 0.4.2.

## Known limitations
This is deterministic orchestration, not a dynamic planner, LLM agent, autonomous external tool runner, or evidence-authenticity verifier. The existing YANTRA approval booleans are not cryptographic owner authentication. Android-device testing is separate from GitHub Actions CI.

## Validation
